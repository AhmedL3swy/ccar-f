5.1

Manage conversation context across long interactions

15

Keep critical information without losing details.

Key points

  • Progressive summarisation can lose important details (numbers, dates, percentages, customer expectations).
  • Place key facts early and use explicit section headers.
  • Keep structured data separate (case facts vs summary).
  • Trim tool outputs to the relevant fields before adding them to context.
  • Include metadata (dates, sources, methodology) in structured outputs.

Info at risk during summarisation

Numeric valuesAmounts, percentages
Dates & deadlines
Customer expectations
Order numbers / statuses

Best practice

  • Extract key facts into a persistent "case facts" block.
  • Use structured formats (tables / JSON) for critical data.
  • Place summaries at the beginning of aggregated inputs.

Avoid

  • Relying only on long conversations without structure.
  • Letting important details get buried in the middle.
5.2

Escalation & ambiguity resolution

17

Know when to escalate and how to handle ambiguity.

Key points

  • Escalate for human help, policy exceptions, or when meaningful progress isn't possible.
  • Tell apart escalating immediately (when explicitly requested) and attempting to resolve straightforward issues.
  • Multiple customer matches need clarification: ask for another identifier.
  • Acknowledge frustration and respond within the agent's capabilities.

Avoid

  • Escalating on silent or ambiguous requests.
  • Using sentiment or low confidence as the only reason to escalate.
  • Assuming you can resolve policy exceptions automatically.

Policy exceptions / gaps
No meaningful progress
Ambiguous customer matchAsk for an identifier first
5.3

Error propagation across multi-agent systems

17

Structured error context for intelligent recovery.

Key points

  • Return structured error context (failure type, attempted query, partial results, alternatives).
  • Distinguish access failures (retry) from valid empty results (success with no matches).
  • Avoid generic errors like "search unavailable".
  • Do not silently suppress errors or terminate entire workflows on single failures.

Avoid

  • Generic error messages.
  • Returning empty results as success.
  • Only propagating errors that can't be resolved locally (share attempted steps and partial results).

Structured error context includes

{
  "error_type": "timeout | validation | permission",
  "attempted_query": "…",
  "partial_results": […],
  "possible_alternatives": […],
  "can_retry": true | false
}
5.4

Context in large codebase exploration

17

Manage context to avoid degradation in long sessions.

Key points

  • Models may give inconsistent answers in long sessions (falling back to "typical patterns").
  • Use scratchpad files to persist key findings across context boundaries.
  • Delegate verbose exploration to subagents.
  • Summarise findings from one phase before spawning subagents for the next.
  • Use compact representations to reduce context usage.

  • Relying on long reasoning chains instead of structured summaries.
5.5

Human review workflows & confidence calibration

17

When to involve humans and how to measure reliability.

Key points

  • Aggregate metrics (e.g. 97% overall) can hide document-type issues.
  • Use stratified sampling to measure error rates and find novel error patterns.
  • Calibrate confidence scores with labelled validation sets.
  • Validate accuracy by document type and field before automating high-confidence extractions.
  • Route low-confidence or ambiguous/contradictory extractions to human review.

Avoid

  • Relying only on aggregate accuracy.
  • Automating high-confidence extraction without validation.
  • Ignoring contradictory sources.
5.6

Information provenance & uncertainty handling

19

Preserve source attribution and handle conflicting info.

Key points

  • Source attribution can be lost during summarisation: preserve claim → source mappings.
  • Require publication / collection dates for temporal data.
  • Handle conflicting statistics by annotating them with sources, not picking a single value.
  • Include source URLs, document names and relevant excerpts in structured outputs.
  • Render each content type appropriately (tables, lists, prose).

Avoid

  • Compressing multiple sources into one undifferentiated summary.
  • Ignoring date requirements for time-sensitive data.
  • Using a single value when sources conflict.

Key takeaways

  1. Preserve critical details (numbers, dates, expectations) in structured formats.
  2. Use explicit summaries and section headers.
  3. Know when to escalate vs resolve.
  4. Return structured error context and handle failures properly.
  5. Use scratchpad files and subagents for large explorations.
  6. Calibrate confidence and validate before automation.
  7. Preserve source attribution and handle conflicting information.

Do vs don't

Do

  • Keep structured case facts.
  • Include metadata and sources.
  • Trim tool outputs to relevant fields.
  • Use explicit escalation criteria.
  • Return detailed error context.
  • Persist key findings (scratchpad).
  • Validate with stratified sampling.
  • Annotate conflicting sources.
  • Handle temporal data with dates.

Don't

  • Let key details get lost in summaries.
  • Use generic error messages.
  • Suppress errors or stop workflows early.
  • Rely on aggregate metrics only.
  • Ignore contradictory sources.
  • Let context grow with irrelevant information.
  • Pick a single value when sources conflict.

    مجموعة تحقق محجوزة على جنب (Held-out validation set) مستندات معلّمة ماتستخدمتش في ضبط البرومبت، بتتستخدم عشان تقيس الدقة وتعاير الدرجات.
  • Stratified random sampling Sampling separately within each segment so rare segments are represented in ongoing audits.
    عينة طبقية عشوائية (Stratified random sampling) إنك تاخد عينات جوه كل شريحة لوحدها، عشان الشرايح النادرة يبقى ليها تمثيل في التدقيق المستمر.
  • Confusion matrix A table showing which categories a classifier confuses with which, revealing errors an accuracy figure hides.
    مصفوفة الالتباس (Confusion matrix) جدول بيوضّح المصنِّف بيلخبط أنهي فئات في أنهي، وبيكشف أخطاء رقم الدقة بيخبّيها.

Key factsمعلومات مهمة 9

  • char_location Citation type for plain-text documents carrying cited_text, document_index, document_title, start_char_index (0-indexed) and end_char_index (exclusive).
    char_location نوع استشهاد لمستندات النص العادي بيشيل cited_text وdocument_index وdocument_title وstart_char_index (العد بيبدأ من 0) وend_char_index (مش داخل في المدى).
  • cited_text The quoted supporting passage; it does not count toward output tokens, nor toward input tokens when passed back in later turns.
    cited_text الفقرة المقتبسة اللي بتدعم المعلومة؛ مش بتتحسب من توكنز المخرجات، ولا من توكنز المدخلات لما تتبعت تاني في أدوار بعد كده.
  • search_result Content block with required source, title and content fields and an optional citations setting with enabled.
    search_result جزء محتوى فيه حقول إجبارية source وtitle وcontent، وإعداد اختياري citations فيه enabled.
  • kb://article-1234 Example of a non-URL stable identifier accepted in a search_result block's source field.
    kb://article-1234 مثال لمعرّف ثابت مش URL ومقبول في الحقل source بتاع جزء من نوع search_result.
  • context field Holds document metadata as text or stringified JSON when documents are passed with citations.
    الحقل context بيشيل البيانات الوصفية بتاعة المستند كنص أو JSON متحوّل لنص لما المستندات تتبعت مع الاستشهادات.
  • <source> tag Prompt-side wrapper for each document, with metadata subtags such as dates.
    الوسم <source> غلاف جوه البرومبت لكل مستند، جواه وسوم فرعية للبيانات الوصفية زي التواريخ.
  • Plain text document type For simple prose; chunked by sentence; cited by character indices (0-indexed).
    نوع المستند: نص عادي للكلام السردي البسيط؛ بيتقسّم لأجزاء على مستوى الجملة؛ والاستشهاد بيبقى بأرقام مواقع الحروف (العد بيبدأ من 0).
  • PDF document type For PDFs with text content; chunked by sentence; cited by page numbers (1-indexed).
    نوع المستند: PDF لملفات PDF اللي فيها محتوى نصي؛ بيتقسّم لأجزاء على مستوى الجملة؛ والاستشهاد بيبقى بأرقام الصفحات (العد بيبدأ من 1).
  • Custom content document type For lists, transcripts, special formatting or more granular citations; no additional chunking; cited by block indices (0-indexed).
    نوع المستند: محتوى مخصّص للقوايم، والمحادثات المتفرّغة نصياً، والتنسيق الخاص، أو الاستشهادات الأدق؛ مفيش أي تقسيم زيادة؛ والاستشهاد بيبقى بأرقام الأجزاء (العد بيبدأ من 0).

Termsمصطلحات 6

  • Provenance The link between a claim and the specific passage that supports it.

  • Claim-source mapping A structured record tying each claim to its source document or URL and supporting excerpt.
    ربط كل معلومة بمصدرها (Claim-source mapping) سجل منظّم بيربط كل معلومة بالمستند أو الـ URL اللي جت منه وبالمقتطف اللي بيدعمها.

    وكيل الاستشهادات (CitationAgent) الوكيل المنفصل في نظام البحث بتاع Anthropic اللي بيربط المعلومات اللي في التقرير المجمّع بأماكنها في المستندات.

    قسم المتنازع عليه (Contested section) الجزء في تقرير التجميع اللي فيه النتائج المتنازع عليها أو اللي من مصدر واحد، والتعارضات متعلّم عليها.
