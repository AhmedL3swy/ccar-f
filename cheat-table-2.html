Domain 2

Tool Design & MCP Integration

18% of exam

Tool descriptions, structured errors, tool scoping, MCP servers and built-in tools.

2.1

Design effective tool interfaces

Clear descriptions, boundaries and examples.

Key points

  • Write clear, distinct tool names and descriptions.
  • Include purpose, expected inputs (with format), outputs and example queries.
  • Add edge cases and boundaries: when to use this tool vs the alternatives.
  • Vague or overlapping descriptions cause misrouting between similar tools.
  • System prompt wording can create unintended keyword associations (e.g. "analyze" in several tools).
  • Split generic tools into purpose-specific ones (e.g. extract_data_points vs summarize_content).

Avoid

  • Minimal or ambiguous descriptions.
  • Overlapping tools with similar names or purposes.
  • Missing input/output details or examples.
2.2

Structured MCP errors

Clear, actionable error responses.

Key points

  • Use the MCP isError flag with structured metadata.
  • Include errorCategory, isRetryable and a human-readable message.
  • Keep a successful empty result distinct from a failure.
  • Recover locally in subagents for transient errors; propagate unresolved failures to the coordinator with partial results and context.

Error response format

{
  "isError": true,
  "errorCategory": "transient | validation | business | permission",
  "isRetryable": boolean,
  "message": "Human-readable explanation"
}

Error categories & handling

Transient
  • Timeout / service unavailable
  • Usually retryable
Validation
  • Invalid input or parameters
  • Needs input correction; not retryable as-is
Business
  • Policy / business-rule violation (e.g. refund above threshold)
  • Usually not retryable
Permission
  • Access denied / missing permissions
  • Needs access resolution or escalation
2.3

Tool allocation & tool_choice

Give the right tools to the right agents.

Key points

  • Too many tools (e.g. 18 instead of 4–5) degrades tool-selection reliability.
  • Give each agent scoped, least-privilege tools relevant to its role.
  • Keep cross-role tools limited to high-frequency needs.
  • Route complex cases through the coordinator.

tool_choice options

auto
  • Default
  • Model may answer with text or call a tool
any
  • Must call a tool
  • Model chooses which tool
forced
  • Must call the named tool
  • {"type":"tool","name":"…"}
none
  • Tools stay defined but cannot be called

Avoid

  • Giving agents access to many unrelated tools.
  • Generic tools instead of constrained alternatives.
  • Cross-specialisation access (agents using tools outside their role).
2.4

Integrate MCP servers

Configure and use MCP servers effectively.

Key points

  • Use project-level .mcp.json for shared team servers.
  • Use user-level ~/.claude.json for personal / experimental servers.
  • Use environment variables (e.g. ${GITHUB_TOKEN}) for credentials; never commit secrets.
  • Tools from configured MCP servers are discovered at connection time and available together.
  • Use MCP resources to expose content catalogues (issue summaries, docs hierarchy, DB schemas) and cut exploratory tool calls.
  • Prefer established community servers for standard integrations (e.g. Jira); build custom servers for team-specific workflows.
  • Improve tool descriptions to explain capabilities and outputs.
  • For local code search, built-in Grep can beat an MCP server.

Configuration files

Project-level (shared).mcp.json · team-wide servers, checked into the repo
User-level (personal)~/.claude.json · personal / experimental servers, not shared
2.5

Built-in tools: Read, Write, Edit, Bash, Grep, Glob

The right tool for file operations and code exploration.

ToolPurposeKey points
GrepSearch file contentsFind patterns (function names, error messages, imports). Best for code content.
GlobFind file paths / namesMatch names or extensions (e.g. **/*.test.tsx). Best for locating files.
ReadRead file contentsRead full content after finding the relevant files.
WriteCreate / overwrite fileNew file, or overwrite full file content.
EditTargeted modificationEdit using unique text matching. If the anchor isn't unique, fall back to Read + Write.
BashRun shell commandsExecute build, test and scripts.

Codebase exploration workflow

1 · GrepFind entry points (function names…)
→
2 · ReadRelevant files only, don't read everything
→
3 · TraceFollow imports / callers to understand flow

Remember

Tool descriptions guide selectionClear, distinct descriptions prevent misrouting.
Structured errors guide recoveryUse errorCategory, isRetryable and clear messages.
Least privilege for each agentGive scoped tools relevant to the agent's role.
Empty result ≠ failureA valid empty result means no matches. That's different from an error.
