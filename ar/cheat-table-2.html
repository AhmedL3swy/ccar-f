2.1

صمّم واجهات أدوات كويسة

5

أوصاف واضحة، حدود، وأمثلة.

أهم النقط

  • اكتب أسامي وأوصاف للأدوات واضحة ومختلفة عن بعض.
  • اكتب الهدف، المدخلات المتوقعة (بشكلها)، المخرجات، وأمثلة أسئلة.
  • ضيف الحالات الحدّية والحدود: إمتى تستخدم الأداة دي وإمتى تستخدم البدائل.
  • الأوصاف المبهمة أو المتداخلة بتخلي الموديل يختار الأداة الغلط بين الأدوات اللي شبه بعض.
  • كلام برومبت النظام ممكن يربط الموديل بكلمات معيّنة من غير قصد (زي كلمة "حلّل" في كذا أداة).
  • قسّم الأدوات العامة لأدوات كل واحدة ليها غرض محدد (زي extract_data_points مقابل summarize_content).

ابعد عن

  • أوصاف قليلة أو مش واضحة.
  • أدوات أساميها أو أغراضها متداخلة وشبه بعض.
  • إنك متكتبش تفاصيل المدخلات والمخرجات أو أمثلة.
2.2

أخطاء MCP المنظّمة

8

ردود أخطاء واضحة تقدر تتصرف على أساسها.

أهم النقط

  • استخدم الحقل isError بتاع MCP مع بيانات وصفية منظّمة.
  • حط errorCategory وisRetryable ورسالة البني آدم يقدر يفهمها.
  • خلي النتيجة الفاضية الناجحة مختلفة عن الفشل.
  • في الأخطاء المؤقتة حاول تتعافى جوه الوكيل الفرعي نفسه؛ والفشل اللي متحلّش ابعته للمنسّق مع النتايج الجزئية والسياق.

شكل رد الخطأ

{
  "isError": true,
  "errorCategory": "transient | validation | business | permission",
  "isRetryable": boolean,
  "message": "Human-readable explanation"
}

أنواع الأخطاء وإزاي تتعامل معاها

Transient
مؤقت
  • المهلة خلصت / الخدمة مش متاحة
  • غالبًا ينفع تعيد المحاولة
Validation
تحقق
  • مدخلات أو معاملات غلط
  • محتاج تصلّح المدخلات؛ مينفعش تعيد المحاولة زي ما هي
Business
قواعد الشغل
  • مخالفة لسياسة أو قاعدة شغل (زي استرداد فلوس فوق الحد)
  • غالبًا مينفعش تعيد المحاولة
Permission
صلاحيات
  • الوصول مرفوض / صلاحيات ناقصة
  • محتاج تحل مشكلة الصلاحيات أو تصعّد
2.3

توزيع الأدوات وtool_choice

7

إدّي كل وكيل الأدوات اللي تناسبه.

أهم النقط

  • أدوات كتير أوي (زي 18 بدل 4–5) بتبوّظ دقة اختيار الأداة.
  • إدّي كل وكيل أدوات محدودة على قد دوره (أقل صلاحيات ممكنة).
  • الأدوات اللي بتعدّي بين الأدوار خليها للحاجات اللي بتتكرر كتير بس.
  • الحالات المعقدة عدّيها على المنسّق.

اختيارات tool_choice

auto
  • الاختيار الافتراضي
  • الموديل يا يرد بنص يا ينادي أداة
any
  • لازم ينادي أداة
  • الموديل هو اللي يختار أنهي أداة
أداة إجبارية
  • لازم ينادي الأداة اللي إنت سمّيتها
  • {"type":"tool","name":"…"}
none
  • الأدوات متعرّفة بس مينفعش تتنادى

ابعد عن

  • إنك تدّي الوكلاء صلاحية على أدوات كتير ملهاش علاقة بشغلهم.
  • أدوات عامة بدل بدائل محدودة ومتظبطة.
  • صلاحيات بره التخصص (وكلاء بيستخدموا أدوات بره دورهم).
2.4

ربط سيرفرات MCP

9

ظبّط سيرفرات MCP واستخدمها صح.

أهم النقط

  • استخدم .mcp.json على مستوى المشروع للسيرفرات المشتركة بين الفريق.
  • استخدم ~/.claude.json على مستوى المستخدم للسيرفرات الشخصية / التجريبية.
  • استخدم متغيرات البيئة (زي ${GITHUB_TOKEN}) لبيانات الدخول؛ وأوعى تعمل كوميت لأي أسرار.
  • أدوات سيرفرات MCP المتظبطة بتتعرف وقت الاتصال وبتبقى متاحة كلها مع بعض.
  • استخدم موارد MCP عشان تعرض كتالوج المحتوى (ملخصات التذاكر، ترتيب المستندات، مخططات قاعدة البيانات) وتقلل استدعاءات الأدوات الاستكشافية.
  • للتكاملات المعروفة (زي Jira) استخدم سيرفرات المجتمع المعروفة؛ واعمل سيرفرات مخصوصة لسير العمل الخاص بالفريق.
  • حسّن أوصاف الأدوات عشان تشرح الأداة بتعمل إيه وبترجّع إيه.
  • في البحث في الكود اللي على جهازك، أداة Grep المدمجة ممكن تكسب سيرفر MCP.

ملفات الإعدادات

على مستوى المشروع (مشترك).mcp.json · سيرفرات لكل الفريق، متسجّلة في المستودع
على مستوى المستخدم (شخصي)~/.claude.json · سيرفرات شخصية / تجريبية، مش متشاركة

2.2 تطبيق ردود أخطاء منظّمة لأدوات MCP
أداة اشتغلت وفشلت (مدخل غلط، أو API برّه واقع)
A tool ran but failed (bad input, upstream API down)
رجّع result عادي فيه isError: true؛ أخطاء JSON-RPC بس للطلبات اللي موصلتش لأداة شغالة أصلاًReturn a normal result with isError: true; JSON-RPC errors are only for requests that never reached a working tool
الأداة بترجّع «Operation failed» عامة وبس
A tool returns only a generic 'Operation failed'
ضيف errorCategory وisRetryable ووصف محدد عشان الوكيل يعرف يختار يتعافى إزايAdd errorCategory, isRetryable and a specific description so the agent can pick a recovery
بتحدد الخطأ ينفع يتعاد ولا لأ
Deciding whether an error is retryable
isRetryable: true بس مع أخطاء transient (timeout أو rate limit)؛ أي حاجة لازم تتغير الأول تبقى falseisRetryable: true only for transient errors (timeouts, rate limits); anything that must change first means false
حقل إجباري ناقص أو صيغته غلط
A required field is missing or has the wrong format
errorCategory: validation وisRetryable: false حتى لو الوكيل يقدر يصلّحه؛ وقول اسم الحقلerrorCategory: validation, isRetryable: false even though the agent can fix it; name the field
التوكن معندوش الدور المطلوب
The token lacks the required role
errorCategory: permission وisRetryable: false؛ هات بيانات دخول بالدور الصح أو صعّدerrorCategory: permission, isRetryable: false; get a credential with the right role or escalate
الوكيل بيعيد طلب ضد السياسة كل شوية
The agent keeps retrying a request that breaks a policy
رجّع errorCategory: business وisRetryable: false وشرح بسيط للعميلReturn errorCategory: business, isRetryable: false and a customer-friendly explanation
«مفيش أوردرات مطابقة» بيتعامل على إنه فشل
'No matching orders' is treated as a failure
نتيجة فاضية صحيحة، مش خطأ؛ isError للاستعلامات اللي مقدرتش تشتغل بس (timeout، مفيش صلاحية)A valid empty result, not an error; isError is for queries that couldn't run (timeout, no access)
المنسّق مش عارف يتصرف إزاي بعد ما وكيل فرعي فشل
The coordinator can't tell how to recover from a subagent failure
سياق خطأ منظّم: نوع الفشل، اللي اتجرّب، النتايج الجزئية، والبدايلStructured error context: failure type, what was tried, partial results, alternatives
2.3 توزيع الأدوات على الوكلاء بشكل مناسب وضبط إعداد اختيار الأداة
وكيل معاه 18 أداة وبيستخدمهم غلط
An agent with 18 tools keeps misusing them
حدد الأدوات حسب الدور (حوالي 4 لـ 5 لكل وكيل) ومعاها كام أداة مشتركةScope tools by role (about 4 to 5 each), plus a few cross-role tools
وكيل بيستدعي أدوات برّه دوره (وكيل الـ QA بيعمل deploy)
An agent calls tools outside its role (a QA agent deploys)
شيلها من قائمة tools بتاعته وخلّي tool_choice على auto؛ any أو none مش هيحلّوهاRemove them from its tools list and keep tool_choice at auto; any or none won't help

The synthesis agent sometimes needs to check a fact
أداة ضيقة verify_fact للتأكيدات البسيطة، والباقي عن طريق المنسّقA narrow verify_fact tool for simple checks; the coordinator for the rest
لازم يحصل استدعاء أداة مش رد نصي
You must get a tool call, not a text reply

tool_choice: {"type": "tool", "name": "..."} في أول دور، وبعدين auto أو anytool_choice: {"type": "tool", "name": "..."} on the first turn, then auto or any

بص على الموديل وإعدادات التفكير؛ واستخدم auto مع strict tool use أو structured outputs بدالهCheck the model and thinking setup; use auto with strict tool use or structured outputs instead
فرض أداة مع التفكير التكيّفي (زي Claude Opus 5)
Forcing a tool with adaptive thinking (e.g. Claude Opus 5)
مسموح، بس الرد بيبدأ باستدعاء الأداة ومن غير كتلة تفكير؛ استخدم auto لو عايزهاAllowed, but the response opens with the tool call and no thinking block; use auto to keep it
