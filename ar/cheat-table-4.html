4.1

الدقة والإنذارات الكاذبة

7

قلّل الإنذارات الكاذبة وزوّد الدقة.

اعمل

  • استخدم معايير صريحة للاكتشاف.
  • حدد قواعد واضحة (بمثال حقيقي) لكل درجة خطورة.
  • ضيف أمثلة لأنماط مقبولة مينفعش تتبلّغ كمشكلة.
  • لو فيه فئة بتطلّع إنذارات كاذبة كتير، اقفلها مؤقتًا، ظبّطها، وجرّبها تاني.

ابعد عن

  • تعليمات مبهمة أو عامة (زي "خليك حذر").
  • تعريفات درجات الخطورة مش ثابتة.
  • إنك تعتمد على الثقة العالية لوحدها، من غير معايير واضحة ودليل.

4.5

الـ Message Batches API

7

عالج طلبات كتير بكفاءة.

استخدمها لما

  • يكون عندك طلبات كتير مستقلة عن بعض.
  • النتايج مش مطلوبة على طول.
  • تقليل تكلفة الـ API مهم (50% من السعر العادي).

ابعد عنها لما

  • الرد مطلوب حالًا (فيه مستخدم مستني).
  • الخطوة الجاية معتمدة على النتيجة الحالية.
  • فيه ميعاد تسليم ضيق محتاج معالجة فورية (الدفعات بتضمن بس ≤ 24 ساعة).

اعمل ومتعملش

اعمل

  • استخدم برومبتات واضحة ومحددة.
  • إدّي أمثلة بتمثّل الحالات الحقيقية.
  • حدد المخرجات المنظّمة بمخطط JSON.
  • اتحقق وابعت رسالة تصحيح محددة.
  • حط المهام الكتير اللي مش مستعجلة في دفعة.
  • استخدم نسخ منفصلة ومراجعات على كذا جولة.

متعملش

  • متستخدمش تعليمات مبهمة.
  • متعتمدش على الثقة العالية لوحدها.
  • متفترضش إن مطابقة المخطط معناها إن الكلام صح.
  • متعيدش المحاولة من غير رسالة تصحيح.
  • متستخدمش الدفعات للطلبات المستعجلة.
  • متراجعش في نفس الجلسة اللي كتبت الكود.

    Unintended pattern An accidental trait shared by all examples, such as length or language, that the model wrongly treats as signal.

    Semantic error A schema-valid value that is wrong relative to the source or to other fields.
  • طبقة التحقق (Validation layer) الكود بتاعك اللي بعد استخراج البيانات واللي بيفرض كل قاعدة المخطط ميقدرش يعبّر عنها.
    Validation layer Your post-extraction code that enforces every rule the schema cannot express.

    Self-correction fields Extra output fields like stated_total and calculated_total that expose discrepancies for code to check.
  • إعادة المحاولة مع إرجاع الأخطاء (Retry with error feedback) طلب متابعة فيه المستند والمخرجات اللي فشلت والأخطاء المحددة عشان الموديل يصلّحها.
    Retry with error feedback A follow-up request carrying the document, the failed output and specific errors so the model can fix them.

    Escalation Stopping automated retries and routing the record to a person who can obtain the missing information.

    Generate-and-evaluate loop A pattern where output is checked against clear criteria and feedback drives the next attempt.
  • تحليل الملاحظات المرفوضة (Dismissal analysis) إنك تجمّع الملاحظات اللي المطورين رفضوها حسب اسم تركيبة الكود عشان تعرف أنهي معيار في البرومبت بيطلّع إنذارات كاذبة.
    Dismissal analysis Grouping developer-dismissed findings by a construct label to find which prompt criterion causes false positives.

  • مهلة الـ 24 ساعة النتايج بتبقى جاهزة لما كل الطلبات تخلص أو بعد 24 ساعة؛ والطلبات اللي متعالجتش مهلتها بتخلص.
    24-hour window Results are ready when all requests finish or after 24 hours; unprocessed requests expire.
  • processing_status حالة الدفعة اللي بتتنقل من in_progress لـ ended، وبعدها تقدر تنزّل نتايج .jsonl.
    processing_status Batch status that goes from in_progress to ended, after which .jsonl results can be downloaded.
  • succeeded / errored / canceled / expired أنواع النتايج الأربعة؛ وsucceeded بس هي اللي بتتحاسب.
    succeeded / errored / canceled / expired The four result types; only succeeded is billed.
  • 400 invalid_request_error (رسالة «البرومبت طويل جداً») المدخل أكبر من نافذة السياق وهيفشل كل مرة لو متقسمش؛ والـ API بتاع عدّ التوكنز يقدر يمسكه قبلها.
    400 invalid_request_error (prompt is too long) Input exceeds the context window and fails every time unless split; the token counting API can catch it beforehand.
  • stop_reason: "pause_turn" دور فيه أداة سيرفر في نتيجة الدفعة مخلصش؛ وعشان تكمّل محتاج طلب جديد.
    stop_reason: "pause_turn" A server-tool turn in a batch result did not finish; continuing requires a new request.

  • دفعة رسائل (Message Batch) مجموعة طلبات Messages API مستقلة بتتعالج بشكل غير متزامن بخصم 50%.
    Message Batch A set of independent Messages API requests processed asynchronously at a 50% discount.
  • معرّف الطلب (custom_id) المعرّف بتاع كل طلب، وهو الرابط الوحيد بين نتيجة الدفعة والمدخل بتاعها.
    custom_id The per-request identifier that is the only link between a batch result and its input.
  • مهلة الانتهاء (Expiry window) حد الـ 24 ساعة اللي بعده طلبات الدفعة اللي متعالجتش مهلتها بتخلص.
    Expiry window The 24-hour limit after which unprocessed batch requests expire.
  • أقصى وقت للتسليم (Worst-case delivery time) الفترة بين كل إرسال والتاني زائد 24 ساعة، ولازم تدخل جوه الـ SLA اللي اتوعدت بيه.
    Worst-case delivery time Submission interval plus 24 hours, which must fit inside the promised SLA.
  • طلب بيتبعت مرة واحدة (Single-shot request) طلب بيتبني كله من الأول ونتيجة واحدة بترجع بعدين، فمفيش حلقة أدوات على ناحية تطبيقك ينفع تشتغل.
    Single-shot request A request built fully up front with one result returned later, so no client-side tool loop can run.
  • أدوات السيرفر (Server tools) أدوات زي البحث على الويب بتشتغل على ناحية المنصة، وعشان كده بتشتغل جوه طلبات الدفعات.
    Server tools Tools like web search that run on the platform side and therefore work inside batch requests.
  • تجربة على الناشف (Dry run) إنك تبعت شكل الطلب على الـ API المتزامن الأول عشان تمسك أخطاء التحقق قبل ما تبعته في دفعة.
    Dry run Sending the request shape through the synchronous API first to catch validation errors before batching.
