1.1

حلقة الوكيل: عشان الوكيل ينفّذ المهام لوحده

6

الحلقة بتشتغل إزاي

  1. ابعت الطلب لـ Claude (الأدوات + الرسايل).
  2. بص على stop_reason.
  3. لو stop_reason طلع "tool_use"، نفّذ الأداة اللي اتطلبت.
  4. ضيف أجزاء tool_use وtool_result على سجل المحادثة.
  5. كمّل الحلقة للّفّة اللي بعدها.
  6. لو stop_reason طلع "end_turn"، اقفل الحلقة.

أهم النقط

  • الموديل هو اللي بيقرر الخطوة الجاية على حسب السياق.
  • نتايج الأدوات بتتضاف للمحادثة عشان Claude يفكّر في الخطوة اللي بعدها.
  • استخدم شجرات قرارات أو تسلسل أدوات ثابت بس لما تحتاجهم بجد.

ابعد عن

  • إنك تحلّل الكلام العادي اللي في الرد عشان تعرف الشغل خلص ولا لأ.
  • حد عشوائي لعدد اللفّات كطريقة أساسية لوقف الحلقة.
  • إنك تعتمد على نص رد Claude عشان تقرر إن الشغل خلص.

سياق الوكيل الفرعي

الوكلاء الفرعيين ليهم سياق معزول ومش بيورثوا سجل محادثة المنسّق خالص.

أهم النقط

  • المنسّق هو اللي ماسك كل التواصل وتوجيه الشغل وتجميع النتايج.
  • اختار الوكلاء الفرعيين وقت التشغيل على حسب صعوبة السؤال.
  • قسّم النطاق عشان الشغل ميتكررش.
  • لف تاني ووزّع الشغل من جديد عشان تسد أي فجوات في التغطية.

ابعد عن

  • تقسيم ضيق أوي يخليك تفوّت مواضيع بحث أوسع.
1.3

استدعاء الوكلاء الفرعيين، تمرير السياق، وإطلاقهم

5

أهم النقط

  • اطلق الوكلاء الفرعيين بالأداة Task (إصدارات الـ SDK الحالية بتطلّعها باسم Agent؛ خلي كودك يتعرّف على الاسمين).
  • لازم allowedTools بتاعة المنسّق يكون فيها أداة إطلاق الوكلاء، وإلا مفيش أي وكيل فرعي هيتنادى.
  • الوكلاء الفرعيين مش بيورثوا سياق الوكيل الأب لوحدهم.
  • ابعت كل السياق المهم بشكل صريح في البرومبت (الملاحظات، روابط المصادر (URLs)، أسماء المستندات، أرقام الصفحات).
  • ظبّط AgentDefinition (الوصف، برومبت النظام، قيود الأدوات).
  • عشان تشغّل وكلاء فرعيين بالتوازي، ابعت كذا استدعاء لـ Task في نفس الرد.
  • استخدم fork_session عشان تجرّب طرق مختلفة من نفس نقطة البداية.

أمثلة للسياق اللي تبعته

  • الملاحظات من الوكلاء اللي قبله
  • نتايج البحث على الويب (الـ URLs)
  • أسماء المستندات
  • أرقام الصفحات
  • نتايج التحليل اللي ليها علاقة

ابعد عن

  • إنك تفترض إن الوكلاء الفرعيين شايفين سياق الوكيل الأب.
  • إنك تسيب سياق محتاجينه عشان التحليل يطلع مظبوط.
1.4

سير العمل اللي فيه كذا خطوة: الإلزام والتسليم

5

أهم النقط

  • استخدم إلزام بالكود (الهوكس، بوابات الشروط المسبقة) عشان الالتزام يبقى مضمون في كل مرة.
  • التعليمات في البرومبت لوحدها احتمالية، يعني دايمًا فيه احتمال إنها تفشل.
  • اقفل استدعاءات الأدوات اللي بعد كده لحد ما الشروط المسبقة تتحقق (مثلًا process_refund محتاج ID عميل متأكدين منه).
  • قسّم الطلبات اللي فيها أكتر من مشكلة، وحقّق فيهم بالتوازي بسياق مشترك.
  • لما تصعّد لموظف بشري، سلّمه ملخص تسليم منظّم.

1.5

الهوكس في الـ Agent SDK: اعتراض استدعاءات الأدوات وتوحيد شكل البيانات

5

أهم النقط

  • هوك PostToolUse: بيمسك نتايج الأدوات ويعدّلها قبل ما الموديل يشتغل عليها.
  • الهوكس اللي قبل الاستدعاء (PreToolUse): بتفرض قواعد الالتزام، زي إنك تمنع أي استرداد فلوس فوق حد معيّن.
  • استخدم الهوكس لما قواعد الشغل تحتاج التزام مضمون.

أمثلة

PostToolUse
  • توحيد شكل البيانات، تظبيط صيغة التواريخ والأوقات، التحويل لشكل منظّم
PreToolUse
  • منع الإجراءات اللي بتخالف السياسة، والتحويل لسير عمل بديل
1.6

استراتيجيات تقسيم المهام في سير العمل المعقد

4

أهم النقط

  • خطوط معالجة ثابتة ورا بعض (سلسلة برومبتات) للمراجعات اللي فيها كذا خطوة وشكلها معروف.
  • تقسيم مرن بيتغيّر مع الوقت للتحقيقات المفتوحة اللي بتمشي على حسب الاكتشافات اللي بتطلع في النص.
  • مراجعات الكود الكبيرة: جولة محلية لكل ملف + جولة منفصلة للتكامل بين الملفات.
  • متشتّتش التركيز على ملفات كتير أوي.
  • المنسّق بيرسم الهيكل، يلاقي الأماكن اللي تأثيرها عالي، ويعدّل الخطة كل ما تظهر اعتماديات جديدة.

أنماط التقسيم

متسلسلسلسلة برومبتات
مرن (بيتكيّف)على حسب الاكتشافات

ابعد عن

  • مراجعات كبيرة من غير ما تفصل تحليل كل ملف عن التكامل بين الملفات.
1.7

حالة الجلسة، تكملتها، وتفريعها

7

أهم النقط

  • استخدم --resume <session-name> عشان تكمّل جلسة ليها اسم، طالما السياق القديم لسه صالح.
  • استخدم fork_session عشان تعمل فروع مستقلة من نفس نقطة بداية التحليل.
  • لما تكمّل جلسة، قول للوكيل إيه الملفات اللي اتغيرت واطلب يعيد تحليلها هي بس.
  • لو نتايج الأدوات القديمة بقت بايتة، ابدأ جلسة جديدة بملخص منظّم.

تستخدم إيه إمتى

تكمّل الجلسة (استئناف)
  • السياق القديم لسه صالح في معظمه
  • عايز تكمّل تحقيق معيّن
  • --resume <session-name>
تفرّع (فرع)
  • تجرّب طرق مختلفة
  • تقارن استراتيجيات بالتوازي
  • fork_session / --fork-session

ابدأ من الأول

  • لما نتايج الأدوات القديمة تبقى بايتة
  • ابدأ بملخص منظّم للاكتشافات اللي فاتت
  • أضمن من إنك تكمّل بسياق قديم

1.1

تصميم وتنفيذ حلقات الوكيل عشان الوكيل ينفّذ المهام لوحدهDesign and implement agentic loops for autonomous task execution

معلومات مهمةKey facts 9

  • stop_reason "tool_use" Claude بيستدعي أداة: شغّلها، ورجّع النتيجة، ولِف لفّة كمان.
    stop_reason "tool_use" Claude is calling a tool: run it, return the result and iterate again.
  • stop_reason "end_turn" Claude خلّص بشكل طبيعي: استخدم الرد، والحلقة خلصت.
    stop_reason "end_turn" Claude finished naturally: use the response, the loop is done.
  • stop_reason "max_tokens" الرد وصل للحد بتاع max_tokens: ارفع الحد أو كمّل الرد.
    stop_reason "max_tokens" The response hit your max_tokens limit: raise the limit or continue the response.
  • stop_reason "pause_turn" حلقة أدوات السيرفر وصلت لأقصى عدد لفّات: رجّع محتوى المساعد في طلب جديد عشان يكمّل.
    stop_reason "pause_turn" The iteration cap of a server-tool loop was hit: return the assistant content in a new request so it can carry on.
  • stop_reason "refusal" Claude رفض يجاوب: بص على stop_details، وبعدين ابعت الطلب تاني بموديل بديل.
    stop_reason "refusal" Claude refused to answer: check stop_details, then send the request again using a fallback model.
  • "model_context_window_exceeded" بتظهر كمسار لوحدها (بيتعامل معاها كحالة وصول لحد السياق) في مثال كود التوزيع على stop_reason اللي في التوثيق الرسمي.
    "model_context_window_exceeded" Appears as its own branch (handled as a context-limit case) in the documentation's example dispatcher on stop_reason.
  • tool_use_id حقل في كتلة tool_result بيكرّر الـ id بتاع tool_use اللي بيرد عليه.
    tool_use_id Field in a tool_result block that repeats the id of the tool_use it answers.
  • "is_error": true بيعلّم على tool_result اللي محتواه رسالة خطأ، عشان Claude يقدر يشرحها أو يعيد المحاولة.
    "is_error": true Marks a tool_result whose content is an error message so Claude can explain it or retry.
  • error_max_turns النوع الفرعي للنتيجة لما توصل لحد الأدوار قبل ما المهمة تخلص؛ ومفيش حقل result متاح.
    error_max_turns Result subtype when the turn limit is hit before the task finished; no result field is available.

مصطلحاتTerms 7

  • حلقة الوكيل (Agentic loop) الدورة اللي تطبيقك هو اللي بيسوقها: طلب، وتنفيذ أداة، ورجوع النتيجة، وبتتكرر طول ما stop_reason قيمته "tool_use".

    3 to 10 times How many more tokens multi-agent setups used than a single agent on the same task in Anthropic's testing.

    50 subagents What Anthropic's early research agents spawned for simple queries, an example of over-delegation.

  • الوكيل الفرعي أو الطرف (Subagent / spoke) وكيل بيمسك مهمة فرعية واحدة اتسلّمتله في محادثة معزولة خاصة بيه، ومش بيرجّع غير آخر رسالة بتاعته.
    Subagent (spoke) An agent that handles one delegated subtask in its own isolated conversation and returns only its final message.
  • نمط المنسّق والعمّال (Orchestrator-workers) نمط فيه المنسّق بيطلّع المهام الفرعية من المدخلات نفسها وقت التشغيل، بدل ما يستخدم مجموعة ثابتة مكتوبة في الكود.
    Orchestrator-workers A pattern in which the orchestrator works out subtasks from the specific input at runtime rather than using a hardcoded set.
  • جانب من السؤال (Facet) شريحة مستقلة من سؤال البحث (موضوع فرعي، أو مجموعة مصادر، أو نوع مصادر) بتتسلّم لوكيل فرعي واحد بالظبط.
    Facet A distinct slice of a research question (subtopic, source set or source type) assigned to exactly one subagent.
  • فشل في التغطية (Coverage failure) نواقص في المخرجات النهائية سببها جزء من النطاق محدش اتكلّف بيه، مش شغل وحش في الأجزاء اللي اتوزّعت.
    Coverage failure Gaps in the final output caused by scope nobody was assigned, not by poor work on the assigned parts.
  • حلقة التحسين المتكررة (Iterative refinement loop) الدورة اللي المنسّق بيلاقي فيها نواقص في التجميع، ويرجع يكلّف باستعلامات موجّهة، ويجمّع تاني لحد ما التغطية تبقى كفاية.
    Iterative refinement loop The coordinator's cycle of finding gaps in a synthesis, re-delegating targeted queries and re-synthesising until coverage is sufficient.
  • خدمة الوكلاء المُدارة (Managed Agents) التنسيق متعدد الوكلاء في منصة Claude، اللي فيه وكيل واحد بينسّق الباقيين في جلسة واحدة، وكل وكيل فرعي ليه خيط جلسة خاص بيه.
    Managed Agents The Claude Platform's multi-agent orchestration, where one agent coordinates others in a single session and each subagent has its own session thread.

  • نمط المنسّق والعمّال (Orchestrator-workers) نمط متكيّف فيه LLM بيقرر المهام الفرعية وقت التشغيل من المدخلات والنتايج اللي فاتت، ويوزّعها، ويجمّع النتايج.
    Orchestrator-workers Adaptive pattern where an LLM decides subtasks at runtime from the input and earlier findings, delegates them and synthesises results.
  • تشتّت الانتباه (Attention dilution) إن دقة الاسترجاع والتفكير في المعلومات البعيدة عن بعض بيقلّوا كل ما محتوى أكتر يتشارك نفس السياق.
    Attention dilution Loss of retrieval precision and long-range reasoning as more content shares one context.
  • جولة التكامل (Integration pass) جولة في المرحلة التانية على النتايج بتاعة كل ملف، بتفحص الملفات بتتعامل مع بعض إزاي.
    Integration pass A second-stage pass over per-file findings that checks how files interact.
  • الاعتماد على المسار (Path dependency) الخاصية اللي بتخلّي الخطوة الجاية معتمدة على اللي الخطوات اللي فاتت لقته، فمينفعش تكتب الطريق في كود من الأول.
    Path dependency The property that what to do next depends on what earlier steps found, so the route cannot be scripted in advance.

معلومات مهمةKey facts 10

  • claude -n <name> / /rename <name> بتسمّي الجلسة وإنت بتبدأها أو في نصّها (وCtrl+R في قايمة الاختيار كمان بيغيّر الاسم).
    claude -n <name> / /rename <name> Set a session name at startup or during the session (Ctrl+R in the picker also renames).
  • claude -r "<name>" "<prompt>" ترجع على طول لجلسة متسمّية، وتدّي الدور الجاي كجزء من نفس الأمر.
    claude -r "<name>" "<prompt>" Go straight back into a named session, giving the next turn as part of that same command.
  • claude --continue / continue_conversation=True / continue: true بيفتح تاني أحدث جلسة في المجلد الحالي أياً كانت.
    claude --continue / continue_conversation=True / continue: true Reopen whichever session in the current directory is newest.
  • resume=session_id خيار في الـ SDK بيحمّل جلسة معيّنة بالـ ID اللي مسكته من رسالة النتيجة.
    resume=session_id SDK option that reloads one specific session by the ID captured from a result message.
  • --output-format json مخرجات الوضع اللي من غير واجهة تفاعلية، اللي تقدر تطلّع منها session_id (مثلاً بـ jq) وتبعته لـ --resume.
    --output-format json Headless output from which session_id can be extracted (for example with jq) and passed to --resume.
  • fork_session=True / forkSession: true / --fork-session طرق Python وTypeScript والـ CLI إنك تفرّع جلسة بتستأنفها في ID جلسة جديد.
    fork_session=True / forkSession: true / --fork-session Python, TypeScript and CLI ways to branch a resumed session into a new session ID.
  • fork_session() مع up_to_message_id دالة مستقلة في Python بتكتب نسخة متفرّعة من سجل الجلسة، ولو عايز لحد رسالة معيّنة بس، وبترجّع الـ ID بتاعها من غير ما تشغّل الوكيل.
    fork_session() with up_to_message_id Standalone Python function that writes a fork of the transcript, optionally only up to a chosen message, and returns its ID without running the agent.
  • persistSession: false خيار في TypeScript بس للمهام اللي مش محتاجة تحفظ حالة، ومش بيكتب أي حاجة على القرص.
    persistSession: false TypeScript-only option for stateless tasks that writes nothing to disk.
  • ClaudeSDKClient اختيار في Python لمحادثة فيها كذا دور جوه عملية واحدة.
    ClaudeSDKClient Python option for a multi-turn chat within one process.
  • error_max_turns / error_max_budget_usd نتايج الوصول للحدود، وبعدها ممكن تستأنف نفس الجلسة بحد أعلى.
    error_max_turns / error_max_budget_usd Limit results after which the same session can be resumed with a higher limit.

مصطلحاتTerms 7

  • الجلسة (Session) محادثة متخزّنة، بكل استدعاء أداة وكل نتيجة، وممكن تتابعها أو تستأنفها أو تتفرّع منها.
    Session A saved conversation, including every tool call and result, that can be continued, resumed or forked.
  • متابعة آخر جلسة (Continue) إنك ترجع لأحدث جلسة في المجلد الحالي أياً كانت، من غير ما تحتاج تتابع أي ID.
    Continue Returning to whichever session in the current directory is latest, without keeping track of any ID.
  • استئناف جلسة بعينها (Resume) إنك تدخل تاني جلسة معيّنة متحددة بالـ ID، أو بالاسم في الـ CLI.
    Resume Re-entering one specific session identified by ID or, in the CLI, by name.
  • التفرّع (Fork) إنك تنسخ سجل محادثة جلسة في ID جلسة جديد، عشان الأصلية تفضل زي ما هي.
    Fork Copying a session's history into a new session ID so the original stays unchanged.
  • مفتاح الاستئناف (Resume handle) قيمة --resume بيقبلها: ID الجلسة، أو اسم إنت حاطه، أو عنوان متولّد، بس مش اسم العرض الافتراضي.
    Resume handle A value --resume accepts: a session ID, a name you set or a generated title, but not a default display name.
  • ملاحظة التغييرات (Change note) أول برومبت مع الاستئناف بيسمّي بالظبط أنهي ملفات اتغيّرت، عشان هي بس اللي تتقري تاني.
    Change note A first prompt on resume that names exactly which files changed so only those are re-read.
  • بداية بملخص منظّم (Structured summary seed) الاستنتاجات والقرارات والفروقات المحفوظة، مكتوبة في أول برومبت لجلسة جديدة بدل سجل المحادثة القديم.
    Structured summary seed Saved conclusions, decisions and diffs written into a fresh session's first prompt in place of stale history.
