3.1

CLAUDE.md hierarchy, scoping & modular organisation

Organise instructions with the right scope and structure.

Hierarchy & scope

User-level
~/.claude/CLAUDE.md
  • Personal instructions
  • Not shared with the team
  • Applies to all your projects
Project-level
CLAUDE.md or .claude/CLAUDE.md
  • Shared via version control
  • Project-specific context
  • Team standards
Directory-level
CLAUDE.md
  • Applies to a subdirectory
  • Adds detail for specific modules
  • Useful for packages / modules

Modular organisation

  • Use @import (e.g. @path/to/standards.md) to include external standards (testing, API rules).
  • Keep topic files in .claude/rules/ (e.g. testing.md).

Avoid

  • Putting team or project standards only in a user-level CLAUDE.md: teammates never receive them.
3.2

Custom slash commands & skills

Reusable workflows with the right scope and configuration.

Slash commands

Project
.claude/commands/
  • Shared via version control
  • Team-wide availability
Personal
~/.claude/commands/
  • Personal use only
  • Not shared

Skills

Project
.claude/skills/<name>/SKILL.md
  • Reusable workflows
  • On-demand (not always loaded)
  • Frontmatter config
Personal
~/.claude/skills/
  • Personal variants
  • Use distinct names
  • Not shared

Frontmatter options (SKILL.md)

---
name: my-skill
context: fork
allowed-tools: ["Read", "Grep"]
argument-hint: "<description>"
---
  • context: fork → isolates verbose skill output from the main conversation.
  • allowed-tools → restricts tool access.
  • argument-hint → guides required parameters.

Rule of thumb

Skills = on-demand, task-specific workflows. CLAUDE.md = always-loaded general guidance.

3.3

Path-specific rules for conditional loading

Apply rules only to matching files to cut irrelevant context.

How it works

  • Put rule files in .claude/rules/ with YAML frontmatter.
  • Use glob patterns in the paths field.
  • Rules load only when Claude works on matching files.
  • Reduces irrelevant context and token usage.

Example

---
paths:
  - "**/*.test.tsx"
  - "src/api/**"
---

Use glob patterns for broad conventions

  • Patterns like **/*.test.tsx work when conventions span many directories.

Avoid

  • Relying only on directory-level CLAUDE.md when you need file-type-specific rules.
3.4

Plan mode vs direct execution

Choose the mode by task complexity.

Plan mode

  • Complex tasks touching many files
  • Architecture decisions
  • Migrations and large-scale changes
  • Several valid approaches
  • Explore safely before making changes

Example use cases

  • Library migration
  • Microservice restructuring
  • Changes affecting many files
  • Evaluating different approaches

Direct execution

  • Simple, well-scoped changes
  • Small edits or single-function fixes
  • Clear requirements
  • Add a validation check or minor bug fix

Example use cases

  • Fix a single bug
  • Add a small feature
  • Update a few lines

Explore subagent

Use the Explore subagent to isolate verbose discovery output and keep the main conversation focused.

3.5

Iterative refinement techniques

Structured techniques that improve results over time.

  1. Provide 2–3 concrete input/output examplesWhen natural-language descriptions are ambiguous.
  2. Write tests firstCover expected behaviour, edge cases and performance.
  3. Share test failures with ClaudeIterate using the actual failures to guide improvements.
  4. Use the interview patternLet Claude ask questions to surface missing requirements and failure modes.
  5. Address interacting issues togetherFix related issues in a single pass; handle independent issues sequentially.
3.6

CI/CD integration

Run Claude Code in automated pipelines with structured output.

Non-interactive executionUse -p (or --print) to run Claude Code in CI without interactive input.
Independent reviewUse a separate review instance instead of reviewing in the generation session.
Structured outputUse --output-format json and --json-schema for machine-readable, constrained output.
On rerunsInclude previous findings and report only new or unresolved issues to avoid duplicate comments.
Project contextCLAUDE.md gives CI the testing standards, fixtures and review criteria.
Existing tests / fixturesProvide existing test files in context to avoid generating duplicate tests.

Key takeaways

  1. CLAUDE.md = always-loaded general standards.
  2. Skills = on-demand, task-specific workflows.
  3. Plan mode = complex changes and exploration.
  4. Direct execution = simple, well-scoped changes.
  5. .claude/rules/ with glob paths = rules load only for matching files.
  6. -p runs Claude Code non-interactively in CI.
  7. JSON Schema guarantees structured output, not semantic truth.
  8. Use a separate instance for independent reviews.
  9. Provide examples, use tests and iterate with feedback.
  10. Include previous findings on reruns to avoid duplicates.

3.1

Configure CLAUDE.md files with appropriate hierarchy, scoping, and modular organizationاظبط ملفات CLAUDE.md بتسلسل مستويات مناسب ونطاق صح، وقسّمها لأجزاء منظمة

Key factsمعلومات مهمة 10

  • ~/.claude/CLAUDE.md User-level instructions that load in every project on your machine and are never committed.
    ~/.claude/CLAUDE.md تعليمات على مستوى المستخدم بتتحمّل في كل مشروع على جهازك وعمرها ما بتتعمل كوميت.
  • ./CLAUDE.md or ./.claude/CLAUDE.md Project-level instructions shared with the team through source control.
    ./CLAUDE.md أو ./.claude/CLAUDE.md تعليمات على مستوى المشروع بتتشارك مع الفريق عن طريق نظام التحكم في النسخ.
  • ./CLAUDE.local.md Personal instructions for one project (e.g. your sandbox URLs); add it to .gitignore.
    ./CLAUDE.local.md تعليمات شخصية لمشروع واحد (زي روابط URL بتاعة بيئة التجربة عندك)؛ ضيفه في .gitignore.
  • Managed policy CLAUDE.md paths On macOS /Library/Application Support/ClaudeCode/CLAUDE.md; on Linux and WSL /etc/claude-code/CLAUDE.md; on Windows C:\Program Files\ClaudeCode\CLAUDE.md.
    مسارات ملف CLAUDE.md بتاع السياسة المُدارة على macOS /Library/Application Support/ClaudeCode/CLAUDE.md؛ وعلى Linux وWSL /etc/claude-code/CLAUDE.md؛ وعلى Windows C:\Program Files\ClaudeCode\CLAUDE.md.
  • managed-settings.json Enforced managed settings that cannot be overridden by personal settings or --settings (few exceptions); can carry instruction text in claudeMd and block tools with permissions.deny or enable sandboxing.
    managed-settings.json إعدادات مُدارة بتتفرض ومينفعش الإعدادات الشخصية أو --settings يلغوها (إلا استثناءات قليلة)؛ وممكن تشيل نص تعليمات في claudeMd، وتمنع أدوات بـ permissions.deny أو تفعّل تشغيل الأدوات في بيئة معزولة.
  • /memory Lists the CLAUDE.md and memory files in scope for the session and lets you open them for editing.
    /memory بيعرض ملفات CLAUDE.md وملفات الذاكرة اللي في نطاق الجلسة، ويخليك تفتحها وتعدّلها.
  • /compact Compacts the conversation whenever you invoke it; the project's root CLAUDE.md is then reloaded from disk, and nested files return only when needed.
    /compact بيضغط المحادثة في أي وقت تشغّله فيه؛ وبعدها ملف CLAUDE.md اللي في جذر المشروع بيتحمّل تاني من على القرص، وملفات المجلدات الفرعية مش بترجع غير وقت الحاجة.
  • ~/.claude/projects/<project>/memory/ Where auto memory notes are stored; not committed, so a fresh clone does not get them.
    ~/.claude/projects/<project>/memory/ المكان اللي بتتخزن فيه ملاحظات الذاكرة التلقائية؛ متعملهاش كوميت، فالنسخة الجديدة من المستودع مش بتاخدها.
  • @path / @~/... Import syntax inside CLAUDE.md that loads the referenced file at launch; external imports require approval.
    @path / @~/... صيغة الاستيراد جوه ملف CLAUDE.md اللي بتحمّل الملف المذكور أول ما تفتح؛ والاستيراد من برا المشروع محتاج موافقة.
  • About 200 lines Recommended maximum size for each CLAUDE.md file.
    حوالي 200 سطر أقصى حجم منصوح بيه لكل ملف CLAUDE.md.

Termsمصطلحات 7

  • Managed policy Organization-wide instruction or settings files deployed by IT/DevOps to system locations, outside developer control.
    السياسة المُدارة مركزياً (Managed policy) ملفات تعليمات أو إعدادات على مستوى المؤسسة كلها، فريق IT أو فريق التشغيل بينزّلوها في أماكن على مستوى نظام التشغيل، برا تحكم المطوّر.
  • Project instructions A committed ./CLAUDE.md or ./.claude/CLAUDE.md that every teammate who clones the repo receives.
    تعليمات المشروع (Project instructions) ./CLAUDE.md أو ./.claude/CLAUDE.md متعمله كوميت، وأي حد في الفريق ياخد نسخة من المستودع بيوصله.
  • Directory-level CLAUDE.md A CLAUDE.md placed in a subdirectory to hold the conventions of one module. If Claude is launched in that directory or beneath it, the file loads at startup; otherwise it loads once Claude reads files in that directory.
    ملف CLAUDE.md لمجلد معين (Directory-level CLAUDE.md) ملف CLAUDE.md متحط في مجلد فرعي عشان يشيل معايير وحدة واحدة من الكود. لو Claude اتفتح في المجلد ده أو تحته، الملف بيتحمّل في الأول؛ غير كده بيتحمّل أول ما Claude يقرا ملفات في المجلد ده.
  • Auto memory Personal, uncommitted notes that Claude records for its own use in ~/.claude/projects/<project>/memory/.
    الذاكرة التلقائية (Auto memory) ملاحظات شخصية متعملهاش كوميت، Claude بيسجلها لاستخدامه هو في ~/.claude/projects/<project>/memory/.
  • Compaction Claude Code summarizing the conversation to free context space, triggered on demand with /compact.
    ضغط السياق (Compaction) إن Claude Code يلخّص المحادثة عشان يفضّي مساحة في السياق، وبتشغّله وقت ما تحب بـ /compact.
  • @path import A reference in CLAUDE.md that pulls another file's content into the instructions at launch.
    الاستيراد بعلامة @ (@path import) إشارة جوه ملف CLAUDE.md بتسحب محتوى ملف تاني جوه التعليمات أول ما تفتح.
  • Rules file A topic markdown file in .claude/rules/; without paths frontmatter it loads every session like CLAUDE.md.
    ملف قواعد (Rules file) ملف ماركداون لموضوع معين في .claude/rules/؛ ولو مفيهوش paths في ترويسة الملف بيتحمّل في كل جلسة زي ملف CLAUDE.md.
3.2

Create and configure custom slash commands and skillsاعمل أوامر سلاش ومهارات مخصصة واظبط إعداداتها

Key factsمعلومات مهمة 10

  • .claude/commands/<name>.md Command file format; the command name is the filename, and subfolders become : prefixes such as /frontend:component.
    .claude/commands/<name>.md شكل ملف الأمر؛ اسم الأمر هو اسم الملف، والمجلدات الفرعية بتتحول لبادئات بـ : زي /frontend:component.
  • .claude/skills/<name>/SKILL.md Project skill, shared once committed; ~/.claude/skills/<name>/SKILL.md is personal and loads in all your local projects but not in Cowork or cloud sessions.
    .claude/skills/<name>/SKILL.md مهارة مشروع، بتبقى مشتركة أول ما تتعمل كوميت؛ و~/.claude/skills/<name>/SKILL.md شخصية وبتتحمّل في كل مشاريعك اللي على جهازك، بس مش في Cowork ولا في الجلسات السحابية.
  • Enterprise skills .claude/skills/<skill-name>/SKILL.md inside the managed settings directory, available to all users where the organization deploys it.
    مهارات المؤسسة .claude/skills/<skill-name>/SKILL.md جوه مجلد الإعدادات المُدارة، ومتاحة لكل المستخدمين في أي مكان المؤسسة بتنزّلها فيه.
  • $ARGUMENTS, $ARGUMENTS[0], $0 Placeholders for all input or a single positional argument; arguments: [issue, branch] names positions as $issue and $branch.
    $ARGUMENTS, $ARGUMENTS[0], $0 علامات استبدال للمُدخل كله أو لمُعامل واحد على حسب مكانه؛ وarguments: [issue, branch] بيدّي أسماء للأماكن دي: $issue و$branch.
  • argument-hint Autocomplete hint for expected input; Claude Code only, rejected by uploads that accept just name, description, license, compatibility, metadata and allowed-tools.
    argument-hint تلميح في الإكمال التلقائي للمُدخل المتوقع؛ في Claude Code بس، وأماكن رفع المهارات بترفضه لأنها بتقبل name وdescription وlicense وcompatibility وmetadata وallowed-tools بس.
  • allowed-tools The listed tools are pre-approved only during the turn in which the skill is invoked; once you send another message, that approval lapses.
    allowed-tools الأدوات اللي فيه بتاخد موافقة مسبقة في الدور اللي اتنادت فيه المهارة بس؛ وأول ما تبعت رسالة تانية، الموافقة دي بتنتهي.
  • disallowed-tools Removes the listed tools from Claude's pool while the skill is active.
    disallowed-tools بيشيل الأدوات اللي فيه من مجموعة الأدوات المتاحة لـ Claude طول ما المهارة شغالة.
  • context: fork with agent Runs the skill in a subagent of the named type (e.g. Explore); model sets the subagent's model and background: false makes the invoking turn wait.
    context: fork مع agent بيشغّل المهارة في وكيل فرعي من النوع المحدد (زي Explore)؛ وmodel بيحدد الموديل بتاع الوكيل الفرعي، وbackground: false بيخلي الدور اللي نادى المهارة يستنى.
  • disable-model-invocation: true / user-invocable: false The first restricts starting the skill to people; the second removes it from the / menu, leaving Claude as the only one able to invoke it.
    disable-model-invocation: true / user-invocable: false الأول بيخلي تشغيل المهارة للبني آدمين بس؛ والتاني بيشيلها من قائمة /، فيبقى Claude هو الوحيد اللي يقدر يناديها.
  • Bundled aliases /reset and /new are aliases of /clear, and /review is an alias of /code-review. A custom skill is able to take the primary name, though not the alias.
    الأسماء البديلة الجاهزة /reset و/new أسماء بديلة لـ /clear، و/review اسم بديل لـ /code-review. المهارة المخصصة تقدر تاخد الاسم الأساسي، لكن مش الاسم البديل.

3.3

Apply path-specific rules for conditional convention loadingطبّق قواعد مربوطة بمسارات معينة عشان المعايير تتحمّل بس وقت ما تلزم

Key factsمعلومات مهمة 9

  • paths The only frontmatter field for rule files; a YAML list or comma-separated string of globs, and omitting it makes the rule apply everywhere.
    paths الحقل الوحيد في ترويسة ملفات القواعد؛ عبارة عن قائمة YAML أو نص من أنماط المسارات مفصولة بفواصل، ولو شيلته القاعدة بتتطبق في كل حتة.
  • * Matches within a single directory level only.
    * بتطابق جوه مستوى مجلد واحد بس.
  • ** Matches across any number of nested directories.
    ** بتطابق عبر أي عدد من المجلدات المتداخلة.
  • **/*.ts TypeScript files in any directory of the repo.
    **/*.ts ملفات TypeScript في أي مجلد في المستودع.
  • *.md Markdown files in the project root only.
    *.md ملفات Markdown اللي في جذر المشروع بس.
  • src/**/*.{ts,tsx} Every .ts or .tsx file inside src/, however deeply nested.
    src/**/*.{ts,tsx} أي ملف .ts أو .tsx جوه src/، مهما كان متداخل لتحت.
  • src/api/**/*.ts Only TypeScript files inside src/api/, nested to any level; nothing elsewhere in src/ matches.
    src/api/**/*.ts ملفات TypeScript اللي جوه src/api/ بس، في أي مستوى تداخل؛ ومفيش أي حاجة تانية في src/ بتطابق.
  • terraform/* vs terraform/**/* The first matches only files directly inside terraform/; the second covers the whole tree.
    terraform/* مقابل terraform/**/* الأول بيطابق الملفات اللي جوه terraform/ على طول بس؛ والتاني بيغطي الشجرة كلها.
  • **/*.test.tsx Component test files wherever they live, including __tests__ folders and a root tests/ folder.
    **/*.test.tsx ملفات اختبارات المكوّنات في أي مكان موجودة فيه، ومن ضمنها مجلدات __tests__ ومجلد tests/ اللي في الجذر.

Termsمصطلحات 6

  • Path-scoped rule A .claude/rules/ file with paths globs that loads only when Claude works with a matching file.
    قاعدة مربوطة بمسارات (Path-scoped rule) ملف .claude/rules/ فيه أنماط مسارات في paths، ومش بيتحمّل غير لما Claude يشتغل على ملف بيطابق.
  • Unscoped rule A .claude/rules/ file without paths that loads every session like CLAUDE.md.
    قاعدة من غير نطاق (Unscoped rule) ملف .claude/rules/ من غير paths، بيتحمّل في كل جلسة زي ملف CLAUDE.md.
  • Glob pattern A wildcard file pattern, using *, ** and braces, matched against paths from the project root.
    نمط مسارات (Glob pattern) نمط لأسماء الملفات فيه رموز بدل، بيستخدم * و** والأقواس المعقوفة، وبيتطابق مع المسارات من جذر المشروع.
  • Brace alternatives A {a,b} group inside one glob that matches any of the listed options, such as two file extensions.
    البدائل جوه الأقواس المعقوفة (Brace alternatives) مجموعة {a,b} جوه نمط مسارات واحد بتطابق أي اختيار من اللي فيها، زي امتدادين مختلفين للملفات.
  • Root anchoring The fact that patterns are matched from the repository root unless they begin with **/.
    الربط بالجذر (Root anchoring) إن الأنماط بتتطابق من جذر المستودع، إلا لو بادئة بـ **/.
  • Conditional loading Bringing instructions into context only when relevant files are touched instead of at every session start.
    التحميل المشروط (Conditional loading) إنك تدخّل التعليمات في السياق بس لما الملفات اللي ليها علاقة تتلمس، بدل ما تتحمّل مع بداية كل جلسة.
3.4

Determine when to use plan mode vs direct executionحدد إمتى تستخدم وضع التخطيط وإمتى تنفّذ على طول

Key factsمعلومات مهمة 9

  • claude --permission-mode plan Launches Claude from the CLI already in plan mode.
    claude --permission-mode plan بيشغّل Claude من واجهة CLI وهو في وضع التخطيط من الأول.
  • Shift+Tab Switches permission mode mid-session in the CLI, including into plan mode.
    اختصار Shift+Tab بيغيّر وضع الصلاحيات في نص الجلسة في واجهة CLI، ومن ضمنها التحويل لوضع التخطيط.
  • default Runs reads only without asking; suited to sensitive work where you review every action.
    default بيشغّل القراية بس من غير ما يسأل؛ مناسب للشغل الحساس اللي بتراجع فيه كل إجراء.
  • acceptEdits Performs reads and file edits, plus routine filesystem commands (mkdir, touch, mv, cp), with no prompt.
    acceptEdits بيعمل القراية وتعديل الملفات، ومعاهم أوامر نظام الملفات العادية (mkdir وtouch وmv وcp)، من غير ما يطلب إذن.
  • auto Runs everything with background safety checks; for long tasks and reducing prompt fatigue.
    auto بيشغّل كل حاجة مع فحوصات أمان في الخلفية؛ للمهام الطويلة وعشان يقلل الزهق من كتر طلبات الإذن.
  • bypassPermissions Runs everything without asking; intended only for isolated containers and VMs.
    bypassPermissions بيشغّل كل حاجة من غير ما يسأل؛ ومعمول للحاويات والأجهزة الافتراضية المعزولة بس.
  • permissions.blockReadsOutsideWorkingDirectories When on, file-reading Bash commands targeting paths outside the working directories prompt in every mode.
    permissions.blockReadsOutsideWorkingDirectories لما يبقى شغال، أوامر Bash اللي بتقرا ملفات في مسارات برا مجلدات الشغل بتطلب موافقة في كل الأوضاع.
  • CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1 Removes the built-in Explore and Plan subagents so exploration runs in the main conversation.
    CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1 بيشيل الوكيل الفرعي Explore ووكيل التخطيط الفرعي المدمجين، فالاستكشاف بيشتغل في المحادثة الأساسية.
  • Explore subagent tools Read-only, with Write and Edit denied, in its own context window.
    أدوات الوكيل الفرعي Explore للقراية بس، والأداتين Write وEdit ممنوعين، وشغال في نافذة سياق خاصة بيه.

Termsمصطلحات 6

  • Permission mode The session setting that decides which actions Claude Code runs without asking.
    وضع الصلاحيات (Permission mode) إعداد الجلسة اللي بيحدد أنهي إجراءات Claude Code ينفذها من غير ما يسأل.
  • Plan mode A permission mode that permits investigation and planning but blocks edits until the plan is approved.
    وضع التخطيط (Plan mode) وضع صلاحيات بيسمح بالبحث والتخطيط، لكن بيمنع التعديلات لحد ما الخطة يتوافق عليها.
  • Direct execution Making a change immediately in an editing mode because the scope and approach are already known.
    التنفيذ المباشر (Direct execution) إنك تعمل التغيير على طول في وضع تعديل، عشان النطاق والطريقة معروفين أصلاً.
  • Explore subagent A built-in read-only subagent for discovery and code search that returns only a summary to the main conversation.
    الوكيل الفرعي Explore (Explore subagent) وكيل فرعي مدمج للقراية بس، معمول للاستكشاف والبحث في الكود، وبيرجّع ملخص بس للمحادثة الأساسية.
  • Plan subagent A built-in read-only subagent for codebase research in support of planning.
    وكيل التخطيط الفرعي (Plan subagent) وكيل فرعي مدمج للقراية بس، بيبحث في الكود عشان يساعد في التخطيط.
  • Auto mode classifier The background check that reviews actions in auto mode and can approve commands in plan mode when auto mode is available.
    مصنِّف الوضع التلقائي (Auto mode classifier) الفحص اللي شغال في الخلفية وبيراجع الإجراءات في وضع auto، وممكن يوافق على أوامر في وضع التخطيط لما الوضع التلقائي يبقى متاح.
3.5

Apply iterative refinement techniques for progressive improvementاستخدم أساليب التحسين على مراحل عشان تحسّن النتيجة خطوة بخطوة

Key factsمعلومات مهمة 6

  • 2–3 examples Recommended number of concrete input/output pairs; start with one and add more only if output still mismatches.
    2–3 أمثلة العدد المنصوح بيه من أزواج المُدخلات والمخرجات الملموسة؛ ابدأ بواحد وضيف أكتر بس لو المخرجات لسه مش مطابقة.
  • Two failed corrections The point at which to stop correcting and restart with a better prompt.
    تصحيحتين فاشلين النقطة اللي توقف عندها التصحيح وتبدأ من الأول ببرومبت أحسن.
  • /clear Clears the conversation so you can start over with an improved initial prompt.
    /clear بيمسح المحادثة عشان تبدأ من الأول ببرومبت أولاني أحسن.
  • AskUserQuestion Tool named in the interview prompt for Claude to question you before building.
    AskUserQuestion الأداة اللي بتتذكر في برومبت المقابلة عشان Claude يسألك قبل ما يبني.
  • SPEC.md Example output file where the interview's complete spec is written.
    SPEC.md مثال لملف مخرجات بيتكتب فيه المواصفات الكاملة اللي طلعت من المقابلة.
  • Test suite coverage Tests written before implementation should cover expected behaviour, edge cases and performance requirements.
    تغطية مجموعة الاختبارات الاختبارات اللي بتتكتب قبل التنفيذ لازم تغطي السلوك المتوقع والحالات الطرفية ومتطلبات الأداء.

Termsمصطلحات 6

  • Iterative refinement Improving output over several rounds, each giving Claude better information than the last.
    التحسين على مراحل (Iterative refinement) إنك تحسّن المخرجات على كذا جولة، وكل جولة بتدّي Claude معلومات أحسن من اللي قبلها.
  • Input/output examples Concrete inputs paired with exact expected outputs, used as an unambiguous spec for a transformation.
    أمثلة مُدخلات ومخرجات (Input/output examples) مُدخلات ملموسة ومعاها المخرجات المتوقعة بالظبط، بتستخدمها كمواصفات واضحة مفيهاش لبس للتحويل.
  • Test-driven iteration Writing an executable test suite before implementation and using its failures to drive each round.
    التكرار المبني على الاختبارات (Test-driven iteration) إنك تكتب مجموعة اختبارات تتشغّل قبل التنفيذ، وتستخدم حالات الفشل بتاعتها عشان توجّه كل جولة.
  • Interview pattern Having Claude question you about requirements and tradeoffs before any code is written, usually ending in a spec.
    أسلوب المقابلة (Interview pattern) إنك تخلي Claude يسألك عن المتطلبات والمفاضلات قبل ما أي كود يتكتب، وغالباً بتخلص بمواصفات مكتوبة.
  • Independent failures Failures in unrelated code whose fixes do not affect each other, reported one at a time.
    حالات فشل مستقلة (Independent failures) حالات فشل في كود ملوش علاقة ببعض وإصلاحاتها مش بتأثر على بعض، وبتتبلّغ واحدة واحدة.
  • Interacting failures Failures that share a cause or touch the same code, reported together in one message.
    حالات فشل مرتبطة ببعض (Interacting failures) حالات فشل ليها نفس السبب أو بتلمس نفس الكود، وبتتبلّغ مع بعض في رسالة واحدة.
3.6

Integrate Claude Code into CI/CD pipelinesادمج Claude Code في خطوط CI/CD

Key factsمعلومات مهمة 10

  • -p / --print Runs one prompt (plus piped stdin) non-interactively and exits.
    -p / --print بيشغّل برومبت واحد (ومعاه المُدخل القياسي المتمرّر له) من غير تفاعل وبيخرج.
  • --allowedTools Approves the listed tools automatically; for example, Bash(git diff *),Bash(git log *),Bash(git status *),Bash(git commit *) covers only examining the repository and making commits.
    --allowedTools بيوافق تلقائياً على الأدوات اللي فيه؛ مثلاً Bash(git diff *),Bash(git log *),Bash(git status *),Bash(git commit *) بيغطي فحص المستودع وعمل كوميتات وبس.
  • --permission-mode dontAsk Denies every call that would otherwise prompt, while working-directory reads, read-only commands and --allowedTools matches still run.
    --permission-mode dontAsk بيرفض أي استدعاء كان هيطلب إذن، لكن القراية في مجلد الشغل وأوامر القراية بس وأي حاجة بتطابق --allowedTools برضه بتشتغل.
  • --permission-mode acceptEdits Writes files and runs mkdir, touch, mv, cp without prompting, e.g. for a headless lint-fix run.
    --permission-mode acceptEdits بيكتب ملفات ويشغّل mkdir وtouch وmv وcp من غير طلب إذن، زي مثلاً في تشغيل من غير تفاعل لتصليح ملاحظات أداة فحص الكود.
  • --output-format text|json|stream-json Plain text (default), a single JSON object with result, session ID and metadata, or newline-delimited streaming JSON.
    --output-format text|json|stream-json نص عادي (الافتراضي)، أو كائن JSON واحد فيه النتيجة ومعرّف الجلسة والبيانات الوصفية، أو JSON متدفق مفصول بسطور جديدة.
  • .result JSON field holding the free-text answer when --output-format json is used.
    .result حقل في JSON شايل الإجابة النصية الحرة لما تستخدم --output-format json.
  • --json-schema / .structured_output Forces the answer into a JSON Schema shape, returned in the separate .structured_output field.
    --json-schema / .structured_output بيجبر الإجابة تيجي بشكل مخطط JSON، وبترجع في الحقل المنفصل .structured_output.
  • anthropics/claude-code-action@v1 The Claude Code GitHub Action; prompt enables automation mode and claude_args passes CLI flags.
    anthropics/claude-code-action@v1 إجراء GitHub بتاع Claude Code؛ prompt بيشغّل وضع الأتمتة، وclaude_args بيعدّي خيارات CLI.
  • mcp__github_inline_comment__create_inline_comment Inline PR comment tool that must be named in --allowedTools within claude_args.
    mcp__github_inline_comment__create_inline_comment أداة التعليقات على سطور الـ PR، ولازم تتكتب في --allowedTools جوه claude_args.
  • --max-turns Caps the number of turns in an unattended run; pair with workflow timeouts and concurrency controls.
    --max-turns بيحط حد لعدد الأدوار في تشغيل محدش متابعه؛ استخدمه مع مهلات سير العمل وإعدادات التحكم في التزامن.

Termsمصطلحات 6

  • Headless run A non-interactive Claude Code execution started with -p that runs one task and exits.
    التشغيل من غير تفاعل (Headless run) تشغيل لـ Claude Code من غير تفاعل، بيبدأ بـ -p، وبينفذ مهمة واحدة ويخرج.
  • Permission prompt A request for human approval of a tool call, which stalls an unattended run if left unanswered.
    طلب الإذن (Permission prompt) طلب موافقة من بني آدم على استدعاء أداة، ولو محدش رد عليه التشغيل اللي محدش متابعه بيقف.
  • JSON envelope The object produced by --output-format json, containing result, the session ID and metadata.
    غلاف JSON (JSON envelope) الكائن اللي بيطلع من --output-format json، وفيه result ومعرّف الجلسة والبيانات الوصفية.
  • Structured output Schema-conforming output produced with --json-schema and returned in .structured_output.
    مخرجات منظّمة (Structured output) مخرجات مطابقة للمخطط بتطلع بـ --json-schema وبترجع في .structured_output.
  • Automation mode GitHub Action behaviour when a prompt input is set, running without waiting for an @claude mention.
    وضع الأتمتة (Automation mode) سلوك إجراء GitHub لما يبقى فيه مُدخل اسمه prompt، فبيشتغل من غير ما يستنى حد يذكر @claude.
  • claude_args The GitHub Action input that forwards CLI flags such as --allowedTools, --max-turns and --model.
    مُدخل خيارات CLI (claude_args) المُدخل في إجراء GitHub اللي بيعدّي خيارات CLI زي --allowedTools و--max-turns و--model.
